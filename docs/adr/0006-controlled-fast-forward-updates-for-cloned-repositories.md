# 仓库型项目允许受控的 GitHub 快进更新

仓库型项目的“数据更新”可以从 GitHub 获取服务方推送的新快照，但不能直接执行不透明的 `git pull`。流程必须先获取并预览远程变化，显示涉及的文件；只有本地工作区干净、当前分支可 fast-forward，且运营者明确确认时才拉取。拉取后必须校验 `data-center/`、来源清单、日期范围和数据新鲜度。

仅涉及 `data-center/` 与来源清单的更新可作为普通数据更新；若同时包含主题、配置、项目规则或其他文件，必须单独披露影响。存在本地修改、分支分叉或合并需求时立即停止，不自动 stash、reset、切分支或解决冲突。非 Git 的新建型项目继续使用本地数据包校验与归档流程。
