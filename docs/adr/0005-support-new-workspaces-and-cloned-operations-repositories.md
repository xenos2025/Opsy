# 同时支持新建工作区与直接克隆的运营仓库

主入口必须兼容两种客户入口。新建型项目在客户选择的项目根目录中创建默认 `shopify-ops/` 工作区和 `shopify-ops.json` 定位文件；仓库型项目直接读取仓库已有定位文件并沿用其工作区，常见值为 `_project/`。工作区名称不是能力判断条件，定位文件才是权威入口。

自动识别顺序为：优先查找并验证最近的 `shopify-ops.json`；定位目标有效时直接使用且不得重建、迁移或改名；没有定位文件但检测到结构完整的 `_project/` 时，先提出补充定位文件的安全迁移建议；两者都不存在时才提供新建 `shopify-ops/`。初始化始终只新增缺失内容，不覆盖 GitHub 克隆仓库中的配置、数据、主题、项目规则、历史记录或客户定制文件。

这一协议让服务方可以交付完整 GitHub 运营仓库，也让没有现成仓库的客户从轻量工作区开始，同时保持主入口、数据推送和 Skill 行为一致。
