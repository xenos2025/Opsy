# Blog 以店铺角色 + 内容工种 + 工艺引导，不只填文章包字段

Blog 与内容在选题和 Shopify 双批准写入之外，必须先加载 `store-profile.json` 中的 `profile.content_voice`（销售/专家角色）。角色缺失时先问诊并写入档案；草稿必须用该角色说话。内容工种只决定结构（清单、对比表、场景选型等），不替换人声。

默认工种保持全行业通用：场景选型、采购/询盘清单、对比、规格解读、行业/客户场景。可选的「产品短名单」仅在商家已有足够在线 PDP 且主动需要短名单时出现；不得把面料「花型盘点」等单一行业用语写进默认菜单。某一行业的人设（例如提花面料销售）只存在于该店配置，不写进 Skill 默认文案。

V1 不把服务商侧的关键词打分、KD 或 opportunity CSV 搬进 Opsy；不得编造搜索数据。缺少真实场景或商业落点时，系统应先收集素材，而不是产出模板化百科文。文章包字段仍要齐全，但字段完整不等于内容可用。`content_voice` 不阻断店铺连接解锁，但阻断 Blog 草稿 Approval A。
