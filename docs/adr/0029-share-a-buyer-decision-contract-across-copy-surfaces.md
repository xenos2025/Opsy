# 页面、PDP 与 Blog 共用买家决策简报

关键词与运营数据继续负责发现需求，`content_voice` 继续负责谁在说和怎么说；页面、PDP 与 Blog 在起草前共用一份买家决策简报，负责目标买家、要完成的决定、主要回答、事实到买家意义的转换、主张证据、异议、适用边界和下一步。共享模块只提供“准备简报”和“检查决策准备度”两个接口，三类内容通过各自适配规则保留不同结构，避免扩充 `content_voice` 或分别维护三套说服模板。

需求证据与主张证据必须分开：关键词、GSC、GA4 或选题数据可以说明买家关注什么，不能证明商品能力或商业承诺。决策准备度是发布前门槛，不得表述为买家已经接受；实际接受程度只能在发布后根据可用的买家响应证据判断。页面适配规则先作为共享合同的消费者，不在 Opsy V1 中增加页面写入菜单或扩大 Shopify 写入范围。

## Considered Options

- 扩充 `content_voice`：拒绝，因为表达风格与买家决策依据是不同概念，混合后难以复用和校验。
- 页面、PDP、Blog 各写一套规则：拒绝，因为证据、异议与 CTA 规则会重复并逐渐漂移。
- 先建立完整店铺级 Messaging 数据库：暂缓，因为 V1 尚未证明多买家、多 Offer 的持久模型值得增加初学者建档负担。

## Consequences

- V1 把买家决策简报保存在具体页面、商品或文章包中，不先扩张店铺档案 schema。
- PDP 与 Blog 只有在共享决策准备度和各自工艺门槛都通过后，才可进入对应写入批准。
- 页面模块可以复用同一合同，但仍由建站或页面工作流拥有其结构、视觉与发布行为。
