## 建议结果合同

以下是**待实现设计**，不是现有命令或现有 schema。放在现有客户工作区 `outputs/runs/<run-id>/`，不新增第六份长期配置，不复制 Skill 到客户项目。

```text
outputs/runs/<run-id>/
  result.json
  report.md
  handoff.md
```

`result.json` 至少包含：

- `schema_version`、`run_id`、`task_id`、工作流类型、开始/结束时间、时区。
- 本次目标、输入文件及指纹、使用的画像与数据周期、目标店铺/对象。
- 总状态与逐对象状态：本地准备、待输入、待批准、草稿已核验、发布已核验、部分完成、失败、待核验。
- 每个承诺字段的 expected/observed/diff，输出文件、店铺对象 ID、Admin/预览/公开 URL。
- 操作 ID、具体变更范围、已有批准证据、响应检查和回读证据；不保存凭证。
- 缺失项与负责人、下一步、下次启动前需要刷新的证据，以及禁止直接重试的操作。
- 数据任务另含来源、周期、时区、指标定义、不可用字段、比较依据、结论和建议的对应证据。

客户 `report.md` 保持简短，回答：

1. 本次目标完成到什么程度？
2. 哪些商品/文章/分析产物已完成，在哪里看？
3. 哪些字段或对象失败、尚未发布、尚未核验？
4. 哪些地方需要客户补资料或作决定？
5. 下一步是什么，由谁完成，怎样算完成？

“API 接受请求”“草稿创建”“正式发布”“公开页核验”和“SEO/GEO 业务效果”是不同状态，不互相代替。

## Handoff 与恢复原则

- 每次启动，先定位项目与状态，再读该任务最近一份结果和待完成项；保留其他任务产物。
- 已存在 Shopify 对象 ID 时先回读，不从草稿包重新创建同一对象。
- 写入响应超时或未知时，先确认实际状态再决定重试；不能将未知直接当作未执行。
- 复用已确认事实与有效授权，避免让客户重复回答；但输入、店铺、变量或操作范围发生变化后，应重新展示具体变化并取得对应批准。
- Approval A 不等于 Approval B；导入服务方任务也不携带 Shopify 写入授权。
- 使用稳定任务 ID 和版本记录关联“服务方任务、客户选择、实际执行、结果回执”；重新导入不得清空客户记录。
- 本地分析和内容准备也要生成交接产物，不强求每个任务都存在 Shopify 写入结果。

## 独立交付验收

验收环境只安装 Opsy Skill，保留必要宿主工具和 Shopify CLI。不调用另一套运营 Skill 来填补流程。

1. **产品**：普通 CSV/XLSX 加本地图片，确认核心事实，创建最低资料草稿；核验预览与补充清单；补齐后发布，并核对 SKU、所需价格、图片及声明要填写的字段。
2. **Blog**：各跑一次数据选题和 FAQ 冷启动；确认画像、文章、图片、CTA 与 SEO 字段；创建草稿、另行发布并核验结果。
3. **数据**：分别使用完整数据包、仅询盘包、缺指标包、口径不兼容历史包；确认数字、限制、来源和下一动作正确。
4. **中断**：在本地包完成、草稿已创建、批准待发布、媒体处理中、写入响应未知各阶段暂停；新会话仅凭项目产物恢复，不重复创建或宣称未核验的成功。
5. **交接**：服务方导入任务，客户执行其中一项，再生成结果回执；下一轮导入保留已执行记录。

本轮没有执行以上真实店铺验收。后续具体外部操作沿用仓库批准规则；不能用合成测试冒充线上成功。
